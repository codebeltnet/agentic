# Existing source, safe repair, and scoped audit

## Inspect before execution

Accept pasted C#, `.cs`, Markdown/DocFX C# fences, JSON manifests, failing source plus diagnostics, repository examples, and PowerShell invocations. Read the actual source and adjacent prose, frontmatter, UID, project/package pins, tests, and public contracts. Establish expected output/assertions before changing anything. Treat supplied PowerShell as code to inspect, not an extraction script to execute blindly; the helper can extract only its own literal-manifest format without evaluation. Inspect other formats manually using PowerShell's AST and literal data. Preserve any existing manifest options and leading C# directives; the engine owns their validation.

For Markdown, identify a fence by path plus heading/UID and ordinal or source offset, not by the first regex match. Multiple fences can be independent programs, stages of one program, or deliberately partial expressions/method excerpts. Classify context first. Do not turn a partial snippet into an invalid-program finding or add scaffolding to a whole documentation tree. For a partial snippet, retain it, report **Intentionally partial / Unverified standalone**, and offer a separately labeled complete demonstration only when useful. Do not claim the original partial source ran. Ask only if inspection cannot resolve a correctness-affecting choice of sample or intended behavior.

`verify` reads and executes source unchanged. A temporary canonical manifest may wrap the exact complete source, with dependencies/framework justified from context. Adding imports, fixing quoting, adding assertions, or completing a snippet is a source change: report the defect rather than silently repairing it. Normalizing transport encoding without changing decoded C# is allowed and must preserve manifest semantics.

## Repair loop

1. Preserve the original source identity and available failure stdout/stderr, diagnostic, exit status, and environment. Execute the original when feasible and useful; if not executed, say so. Establish intended behavior using prose, source, tests, and published contracts; diagnose before editing.
2. Distinguish source/configuration defects from environment failures and unsupported topology. Check syntax/imports; real type/member signatures and supported obsolete-API replacements; authoritative exact NuGet IDs/versions; framework asset selection; manifest options; PowerShell literal quoting; assertion meaning; and documented/executed-source parity. Do not guess a package replacement or change a target merely to make restore succeed.
3. Make the smallest justified correction. Keep expected values, tested operation, lifecycle, and application assembly identity intact. Strengthen an incomplete assertion only when the intended contract supports it; never weaken assertions or replace the behavior under test to get a pass. A semantic redesign needs an explicit explanation and user direction, not a silent repair.
4. Edit only the authorized region. Preserve encoding/BOM, line endings, frontmatter, headings, links, DocFX directives, UID references, and unrelated fences. Use DocFX's existing structured overwrite writer when appropriate; otherwise the optional `Set-CsrunSourceRegion` helper applies an inspected exact text region and refuses stale source or lossy encoding. It does not parse Markdown or decide repairs. Pass offsets into decoded text, excluding the BOM; use supported encoding explicitly or an appropriate editor for unknown encodings. Inspect the localized diff.
5. Construct one corrected manifest, generate both wrappers, execute corrected source, and verify the declared observation. Record before/after identities and outcomes. Keep failure evidence visible even after success; no success claim until the corrected behavior actually executes. For unavailable environments, report repair made but execution **Unverified**.

The original `InventoryWorkerTest` is a non-repairable standalone topology, not permission to delete `WorkerProgram.Main`. Follow [feasibility](feasibility.md). A manually built host can be a separate reduced demonstration, never proof of the original application startup.

## Deterministic audit

Respect the requested directory/files and parent authorization. Discover candidate `.cs`, `.md`, `.mdoc`, manifest `.json`, and `csrun` `.ps1` inputs in stable ordinal path order. Use existing DocFX discovery/assessment output for DocFX scopes; do not create a second compilation or Markdown interpretation subsystem. Review candidate files in context, recording one row per actual example with path, UID/heading/fence ordinal or source region, exact source hash, canonical manifest hash when applicable, framework, exact dependencies, SDK/framework references, expected observation, feasibility, transport-specific status, evidence path, and diagnostics. Non-sample JSON/PowerShell files are not samples merely because of their extension.

Use these outcomes independently of feasibility: **Verified executable**, **Compiled only**, **Repairable defect**, **Unsupported execution topology**, **Missing environment or dependency**, **Intentionally partial**, or **Already verified with current matching evidence**. A missing published package pin can be a repairable defect; missing private infrastructure may instead be a prerequisite. Report discovery counts and unresolved rows; do not imply all examples passed when some are partial, unsupported, or unexecuted.

Keep the inventory, manifests, logs, and evidence under an OS temporary task directory or ignored `.bot/`, never alongside tracked docs. Process `audit --fix` in manageable batches of eligible source defects; preserve unsupported/partial examples and unrelated content. Verify each corrected canonical identity and summarize changed files and remaining failures.

Reuse evidence only when the user's verification policy permits it and **all** relevant inputs match: exact source, canonical manifest including dependencies/framework/sdk/references, engine hash or image digest, actual SDK/runtime/platform/architecture, resolved package assets/transitive dependencies, expected-observation contract, and relevant external inputs. Record timestamp and evidence provenance. Mutable tags, `latest`, unavailable environment identity, or unknown external state cannot establish a cache match. After any relevant change, execute again. Matching source alone never verifies another transport; previously matched evidence must name that transport. An inventory status or model statement is not execution evidence.
