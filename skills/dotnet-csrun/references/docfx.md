# Compose with dotnet-docfx-digest

`dotnet-docfx-digest` owns public API discovery, documentation structure, namespaces/types/UIDs, example placement, source-backed explanation, repository-aware compilation, DocFX builds, and documentation completion. `dotnet-csrun` owns standalone construction, genuine xUnit v3 execution, portable native/Docker blocks, runtime observations, localized authorized corrections, and reproducible evidence.

Within an authorized documentation task, the parent agent may apply `create` for a compatible self-contained example, `verify` for unchanged existing source, or `repair` for an authorized correction. During a scoped audit, contribute standalone classifications and runtime evidence to the existing DocFX inventory. No deterministic validator launches an agent, model, or another skill. Both skills' tools remain independently usable.

Preserve `docfx.cs --build-api-model --validate-samples --verify-docfx-build`. Its reference-aware compilation remains authoritative for local unpublished APIs, project references, multiple assemblies, application entry points, full hosts/HTTP pipelines, and other unsupported standalone prerequisites. Do not replace those with published packages and claim the checkout was verified. A passing published-package csrun example proves that package version; a compiling project-backed DocFX sample may still be non-runnable standalone.

Do not require every DocFX fence to become a standalone csrun program. Existing partial excerpts are classified in context; DocFX's own rules still govern authoring new examples. A class-library compilation unit without an invoked behavior is **Compiled only**, unless a clearly disclosed complete harness actually invokes and observes it. Adding a harness must preserve the original operation; do not claim byte-identical documented/executed source if the harness changes it. Record the excerpt identity and separately executed complete source identity instead.

Generate both complete transport blocks for compatible csrun deliverables, but let DocFX choose presentation. Keep a concise C# fence as the primary artifact where appropriate, with reusable execution variants linked or placed where useful. Derive fences and wrappers from one manifest source; compare extracted fence source with the manifest before claiming exact traceability. If the documentation intentionally presents an excerpt, label it and record its relationship to the complete executable instead of asserting exact equality.
